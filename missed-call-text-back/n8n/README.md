# Missed Call Text-Back: n8n workflows

These are the seven workflows behind Missed Call Text-Back, exported from n8n. Credentials, workspace IDs and personal details have been removed, so they import cleanly into any n8n workspace.

| File | Workflow | Trigger | What it does |
|---|---|---|---|
| `0-demo-business.json` | Demo Business | Manual, or called by the Dashboard API | Writes default settings if there are none, clears the tables and loads 30 days of a sample plumbing company from `demo-business.json`, moved to today's dates |
| `1-missed-call.json` | Missed Call | Two Twilio voice webhooks, or called by the Dashboard API | Rings the owner's mobile. If nobody answers, tells the caller a text is coming, logs the call and sends the text-back |
| `2-sms-conversation.json` | SMS Conversation | Twilio messaging webhook, or called by the Dashboard API | Handles STOP and START by rule. Otherwise Claude reads the thread, price list and open slots, replies, fills in the job and books it. Texts the owner on emergencies and call-back requests |
| `3-follow-ups.json` | Follow-ups | Every 15 minutes | Nudges callers who never replied after 30 minutes and again the next day, then closes the lead |
| `4-daily-summary.json` | Daily Summary | Every day at 6pm | Emails the owner calls, missed calls, replies, jobs booked and who still needs a call. No AI |
| `5-dashboard-api.json` | Dashboard API | Two webhooks | Serves data to the React dashboard and runs its buttons |
| `9-error-alert.json` | Error Alert | Error trigger | Emails the owner when any of the other workflows fails |

`demo-business.json` is the sample data used by workflow 0. It is generated by `node scripts/demo-data.mjs` from the same code as the public demo.

## Setup

### 1. Create the data tables

In n8n, open **Overview > Data tables** and create these four tables.

**mctb_leads** (one row per conversation)

| Column | Type |
|---|---|
| lead_id, phone, name, status, source, service, issue, urgency, zip, address, offered, booked_by, reason, summary | string |
| value, follow_ups, text_back_seconds, call_count | number |
| urgent, needs_call, ack, ai_paused | boolean |
| slot, first_reply_at, alerted_at, booked_at, created_at, last_at | date |

`status` is one of texted, chatting, urgent, booked, no_reply, lost or opted_out. `offered` holds the offered slot times as a JSON list.

**mctb_calls**

| Column | Type |
|---|---|
| call_id, lead_id, phone, outcome, note | string |
| ring_seconds, duration, text_back_seconds | number |
| at | date |

**mctb_messages**

| Column | Type |
|---|---|
| msg_id, lead_id, phone, dir, author, body | string |
| at | date |

`dir` is in, out or note. `author` is customer, ai, owner or system.

**mctb_settings** (one row, written by workflow 0)

| Column | Type | Example |
|---|---|---|
| settings_key | string | main |
| businessName, shortName, ownerName | string | BrightFlow Plumbing & Heating, BrightFlow, Dan |
| ownerPhone, businessPhone | string | +15125550100, your Twilio number |
| ownerEmail | string | owner@your-business.com |
| currency, timezone | string | $, America/Chicago |
| areaLabel, serviceZips | string | Austin, Cedar Park and Round Rock; 787, 78613 |
| weekdayHours, saturdayHours, slotTimes | string | 07:00-18:00; 08:00-13:00; 08:00, 10:30, 13:00, 15:30 |
| textBack, afterHours | string | The text-back messages. `{business}` becomes the short name |
| claudeModel | string | claude-opus-5 |
| services | string | JSON list of `{ key, name, from, typical, urgent }` |
| vans, ringSeconds, followUpMinutes, finalFollowUpHours | number | 2, 20, 30, 20 |
| aiEnabled, demoMode | boolean | true, true |

### 2. Import the workflows

Import the files in order (**Workflows > Import from file**): `9-error-alert.json`, then `0` to `5`.

After importing, open each workflow and:

1. **Data table nodes:** pick the matching table in every node that shows `SELECT_..._TABLE`.
2. **Twilio nodes:** add a Twilio credential (Account SID and Auth Token).
3. **Claude node** (workflow 2): use n8n's built-in AI credits or add an Anthropic credential.
4. **Gmail nodes** (workflows 4 and 9): connect a Gmail account.
5. **Dashboard API only:** in **Run Missed Call**, **Run SMS Conversation** and **Rebuild Demo Business**, pick workflows `1`, `2` and `0`.
6. **Workflow settings:** publish workflow 9, then set **Error workflow** to *Missed Call Text-Back 9 - Error Alert* in workflows `1` to `5`.

### 3. Try it safely

1. Run **Demo Business** once. It writes the settings row and fills the tables.
2. Keep `demoMode` set to `true`. Every text is logged but nothing goes through Twilio, so you can test with no phone number at all.
3. Publish **Dashboard API**, point the React app at your workspace with `VITE_API_BASE` (see the main README) and use the demo phone on the Live page. Replies now come from Claude.

### 4. Connect a real phone number

1. Buy a number in Twilio and put it in `businessPhone`. Put the owner's mobile in `ownerPhone`.
2. In Twilio, set the number's **A call comes in** webhook to `https://your-workspace.app.n8n.cloud/webhook/mctb-voice` (HTTP POST) and **A message comes in** to `https://your-workspace.app.n8n.cloud/webhook/mctb-sms`.
3. Publish workflows 1, 2, 3 and 4, then set `demoMode` to `false`.

## Before using real customer data

- Add Header Auth to the Dashboard API webhooks and send the same header from the dashboard.
- Turn on Twilio request validation or restrict the voice and messaging webhooks, so only Twilio can post to them.
- Business texting in the US needs A2P 10DLC registration with Twilio. The STOP and START handling in workflow 2 is built in, and opted-out numbers are never texted again.
